# Effect basics and lifecycle

## Interview questions

### Что такое Effect?
<!-- question-id: 10-react-effects-q01 -->
#### Ответ

Effect — механизм React для синхронизации уже закоммиченного UI с внешней системой, которой React не управляет напрямую: сетью, подпиской, таймером, DOM API, media player или сторонним виджетом. Вызов Hook объявляет setup-функцию и, при необходимости, cleanup. Effect — не универсальное место для любого side effect: обработку пользовательского действия обычно делают в event handler, а производное значение вычисляют во время render. Компонент при этом остаётся чистой функцией в render-фазе; эффект запускает взаимодействие после commit. Это модель React 19.2 в репозитории; базовый контракт описан в [React useEffect docs](https://react.dev/reference/react/useEffect).

### Для чего useEffect?
<!-- question-id: 10-react-effects-q02 -->
#### Ответ

useEffect нужен, когда компонент должен установить или поддерживать связь с внешним миром. Например, при смене roomId отключить старое chat connection и подписаться на новую комнату; либо установить listener на window и удалить его при выходе. React запускает setup после commit и повторно синхронизирует его, когда меняются reactive dependencies; cleanup отменяет/отписывает прежнюю настройку. Для загрузки данных в приложении обычно предпочтительны framework loader или query/cache library: они лучше решают deduplication, caching и race handling. Effect с fetch допустим на клиенте, но обязан обработать отмену/устаревший ответ. См. [useEffect](https://react.dev/reference/react/useEffect).

### Когда Effect вообще не нужен?
<!-- question-id: 10-react-effects-q03 -->
#### Ответ

Не нужен, если задача целиком описывается данными React. Производное значение считайте в render (например, const fullName = first + " " + last), а не храните дублирующее state и обновляйте его Effect-ом: это даёт лишний render и риск рассинхронизации. Реакцию на клик/submit выполняйте в соответствующем handler, где известна причина действия; не переносите её в Effect, который косвенно следит за флагом. Для сложного перехода state используйте reducer. Effect оправдан для синхронизации с внешней системой; если убрать его и ничего вне React не останется несинхронизированным, он, вероятно, лишний. Это рекомендуемое направление React docs.

### Что означает Effect без dependency array?
<!-- question-id: 10-react-effects-q04 -->
#### Ответ

Если второй аргумент опущен, React выполняет setup после каждого commit этого компонента. Если setup вернул cleanup, перед следующим setup React сначала вызывает cleanup предыдущего Effect с захваченными им старыми значениями; при unmount cleanup вызывается ещё раз. Это не равнозначно «один раз после каждого вызова функции» — render может быть отменён и не commit-нут. Такой режим уместен только когда внешнюю систему действительно надо синхронизировать после каждого commit; чаще полные dependencies точнее. Если Effect обновляет state, а рендер происходит каждый раз, возможен бесконечный цикл.

### [].
<!-- question-id: 10-react-effects-q05 -->
#### Ответ

Пустой dependency array означает, что setup не читает reactive values текущего компонента, которые должны перезапускать синхронизацию: setup запускается при commit монтирования, затем cleanup при unmount. В dev StrictMode у корня React дополнительно делает setup → cleanup → setup, чтобы проверить симметрию; повторный mount (например, смена key) также запускает эффект заново. Поэтому [] не является гарантией «ровно один раз за жизнь вкладки». Если Effect читает props/state, [] обычно ошибка: callback навсегда использует снимок начального render. Не подавляйте exhaustive-deps; вынесите действительно неизменяемую константу наружу либо измените структуру кода. Официальный контракт: [useEffect dependencies](https://react.dev/reference/react/useEffect).

### [a, b].
<!-- question-id: 10-react-effects-q06 -->
#### Ответ

Массив задаёт полный список reactive values, от которых зависит процесс синхронизации. На первом commit запускается setup; на commit, где хотя бы одна зависимость отличается от предыдущей по Object.is, React запускает старый cleanup, затем новый setup. Длина и порядок массива должны оставаться постоянными и быть записанными inline; пропущенная зависимость создаёт stale closure, лишняя нестабильная зависимость — ненужные reconnects. Включайте все используемые props, state и локальные функции/объекты; stable state setters и ref object обычно не требуют зависимости. Не вычисляйте массив динамически, например из условного числа значений.

### Cleanup.
<!-- question-id: 10-react-effects-q07 -->
#### Ответ

Cleanup — функция, возвращённая из setup, которая закрывает или отменяет ровно тот ресурс, созданный этим запуском: removeEventListener для addEventListener, unsubscribe для subscribe, clearInterval для setInterval, disconnect для connection, AbortController.abort для запроса. Она замыкает значения текущего запуска setup; это полезно, потому что cleanup старой конфигурации должен закрыть именно старый ресурс, даже если props уже изменились. Cleanup не обязателен, если setup не создаёт ресурс и не запускает процесс, который нужно остановить. Не используйте cleanup для симметричного «отката» пользовательского действия без причины; важно, чтобы повторный setup после cleanup был безопасен и визуально эквивалентен одному запуску.

### Когда cleanup выполняется?
<!-- question-id: 10-react-effects-q08 -->
#### Ответ

React вызывает cleanup предыдущего setup перед тем, как после commit запустить новый setup из-за изменения dependency; cleanup видит старые значения, с которыми создал ресурс. При удалении компонента React вызывает финальный cleanup. Без dependency array cleanup/setup повторяются после каждого commit; с [] — только при unmount (плюс dev replay в StrictMode). Cleanup не запускается просто потому, что компонент rerender-нулся, если зависимости не изменились. Важно отличать React commit от визуального paint: для useEffect точный момент относительно paint зависит от причины обновления, но порядок old-cleanup → new-setup сохраняется. [Документация](https://react.dev/reference/react/useEffect).

### Почему effects запускаются после commit?
<!-- question-id: 10-react-effects-q09 -->
#### Ответ

Render в React должен быть чистым и может быть повторён, приостановлен или отброшен concurrent renderer-ом. Если открыть соединение, изменить DOM или поставить таймер внутри render, эффект возникнет даже для UI, которого пользователь никогда не увидит, а повторный render может создать дубликаты. Commit — момент, когда React уже выбрал и применил результат к DOM; запуск Effect после него означает, что внешняя система синхронизируется с реально принятой версией UI. useEffect обычно не блокирует paint; если нужно измерить новый DOM и скорректировать визуальное положение до paint, используйте useLayoutEffect. Детали timing описаны в [React useEffect docs](https://react.dev/reference/react/useEffect).
