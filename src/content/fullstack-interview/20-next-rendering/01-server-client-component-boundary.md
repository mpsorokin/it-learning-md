# Server and Client Component boundary

## Interview questions

### Что Next.js добавляет поверх React?
<!-- question-id: 20-next-rendering-q01 -->
#### Ответ
Next.js — это фреймворк вокруг React: он задаёт файловую маршрутизацию, серверный рендеринг React Server Components, получение данных, потоковую передачу интерфейса, сборку и оптимизацию ресурсов, а также интеграционные соглашения вроде layout.tsx, page.tsx и route.ts. React остаётся моделью компонентов и обновления UI; Next.js выбирает, где и когда их отрендерить, как передать RSC-дерево браузеру и как разложить результат по маршрутам. Это не означает, что всё автоматически быстрее: неверные границы Client Components, последовательные запросы или общий кэш для персональных данных способны ухудшить производительность и безопасность.

### Server Components.
<!-- question-id: 20-next-rendering-q02 -->
#### Ответ
Server Component выполняется в серверной среде при рендеринге маршрута. В App Router layouts и pages по умолчанию серверные. Компонент может читать данные непосредственно из базы/сервиса, использовать секреты на сервере и не отправлять собственный JavaScript в браузер; клиенту уходит его отрендеренный результат в RSC Payload. Он не может использовать state/effect, обработчики событий или browser APIs. Это не граница авторизации само по себе: текст и props, выведенные в результат, доступны клиенту. Для актуальной модели см. [Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components).

### Client Components.
<!-- question-id: 20-next-rendering-q03 -->
#### Ответ
Client Component нужен там, где есть интерактивность: state, обработчики событий, эффекты или браузерные API. Его файл и импортируемый им модульный граф входят в клиентский bundle. Важная оговорка: на первом запросе Client Components обычно тоже участвуют в серверной генерации HTML, а затем браузер гидратирует их; «client» не значит «никогда не запускается на сервере». На последующих переходах клиент использует RSC-ответ и исполняет клиентскую часть браузером. Поэтому границу стоит ставить как можно ниже по дереву и передавать сериализуемые props.

### 'use client'.
<!-- question-id: 20-next-rendering-q04 -->
#### Ответ
Директива 'use client' ставится в начале модуля до импортов и помечает точку входа в Client Component graph. Это не директива для каждого вложенного компонента: все импорты от этой точки считаются клиентскими зависимостями и могут попасть в JS bundle. Через такую границу нельзя импортировать серверный модуль с секретами, доступом к файловой системе или базой. Server → Client props должны сериализоваться React. Директива задаёт границу графа модулей, а не переключает весь UI приложения в CSR; актуальное описание: [документация Next.js](https://nextjs.org/docs/app/getting-started/server-and-client-components).

### Где проходит client/server boundary?
<!-- question-id: 20-next-rendering-q05 -->
#### Ответ
Граница проходит по графу импортов модулей. Модуль без 'use client', импортируемый серверным page/layout, остаётся Server Component. Модуль с 'use client' становится корнем клиентской части; его импорты также клиентские. При рендеринге сервер передаёт в клиентскую часть только совместимые с сериализацией props и результат серверного поддерева. Поэтому разделяйте UI-композицию и доступ к данным: серверная функция должна оставаться на сервере, а интерактивная кнопка получает только минимальные данные. Случайное расширение клиентского графа повышает размер JS и может раскрыть код, который не должен исполняться в браузере.

### Можно ли Server Component импортировать в Client Component?
<!-- question-id: 20-next-rendering-q06 -->
#### Ответ
Обычный импорт Server Component из файла с 'use client' не сохраняет серверное исполнение: импорт попадает в клиентский граф и часто ломается на server-only API, секретах или асинхронной серверной логике. Рекомендуемая композиция — импортировать Client Component в серверном родителе и передать отрендеренный Server Component через children или другой slot-проп. Тогда серверная часть остаётся серверной, а клиент управляет оболочкой, например открытием модального окна. Эти узлы всё равно должны образовывать допустимое сериализуемое RSC-представление. См. раздел Interleaving в [официальной документации](https://nextjs.org/docs/app/getting-started/server-and-client-components).

### Можно ли Client Component использовать внутри Server Component?
<!-- question-id: 20-next-rendering-q07 -->
#### Ответ
Да. Server Component может импортировать и отрисовать Client Component как потомка. Сервер сформирует HTML-предпросмотр и RSC-запись с клиентским компонентом, его JS-ссылкой и сериализуемыми props; браузер затем гидратирует этот участок. Сам импорт клиентского компонента не превращает серверного родителя и соседние ветви в клиентские. Так обычно и строят экран: данные и статическая оболочка остаются на сервере, а небольшие интерактивные элементы выделяются в клиентские компоненты. Не передавайте через props функции или приватные данные, если они не поддерживаются протоколом и не предназначены клиенту.
