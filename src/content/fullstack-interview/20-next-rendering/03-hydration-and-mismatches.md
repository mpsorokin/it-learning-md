# Hydration and mismatches

## Interview questions

### Что такое hydration?
<!-- question-id: 20-next-rendering-q13 -->
#### Ответ
Hydration — этап, на котором React сопоставляет HTML, уже показанный браузером, с React-деревом Client Components и подключает интерактивность: обработчики, state и эффекты. Она не равна первичному созданию HTML и не означает, что все серверные компоненты «запускаются повторно» в браузере. Первичная серверная разметка и первый клиентский render должны совпасть по структуре и значениям, иначе возникает hydration mismatch. В App Router RSC Payload помогает восстановить дерево до/в процессе гидратации клиентских частей.

### Что именно hydration делает?
<!-- question-id: 20-next-rendering-q14 -->
#### Ответ
React берёт DOM, созданный сервером, строит соответствующее клиентское представление и связывает его с DOM-узлами, устанавливая обработчики и восстанавливая механизм state. Это позволяет избежать полного повторного создания документа и показать HTML до завершения загрузки JS. Hydration требует совместимого начального вывода: например, условие на window, текущее время или случайный ID не должны менять результат между сервером и первым браузерным render. После гидратации обычные обновления React уже изменяют DOM согласно клиентскому state; серверные компоненты при этом остаются серверными.

### Hydration mismatch.
<!-- question-id: 20-next-rendering-q15 -->
#### Ответ
Hydration mismatch — ситуация, когда HTML, полученный с сервера, отличается от того, что React ожидает при первом render в браузере. Это может вызвать предупреждение, неверные обработчики или перестроение части DOM, а в некоторых случаях — визуальный скачок и потерю первоначального состояния. Диагностируйте конкретный узел по сообщению React/Next, сравните серверный HTML с первым клиентским render и проверьте данные, локаль, ветвления и структуру HTML. Не маскируйте mismatch общим suppressHydrationWarning: он оправдан только для узкого неизбежного текстового расхождения.

### Частые причины mismatch.
<!-- question-id: 20-next-rendering-q16 -->
#### Ответ
Типичные источники: Date.now() или Math.random() в render; локаль/часовой пояс, отличающиеся на сервере и клиенте; чтение window, localStorage или viewport при построении начального JSX; разные данные из гонки обновления; некорректная вложенность HTML, которую браузер исправляет до React; условная разметка по user agent; расширение браузера, меняющее DOM. Фикс — передать один snapshot с сервера, генерировать стабильные IDs, нормализовать locale/timezone и сделать одинаковую начальную ветку. Для чисто клиентского значения можно после mount прочитать API в effect, но пользователь увидит переход от placeholder к данным; учитывайте CLS и доступность.
