# Utility types: основы

## Interview questions

### Partial.
<!-- question-id: fullstack-interview-03-typescript-core-029 -->

#### Ответ

Partial<T> — mapped type, делающий все свойства T необязательными и сохраняя их типы, включая исходные readonly-модификаторы. Он удобен для patch/update DTO, где отсутствие поля означает «не менять», но не эквивалентен Partial<T> с контролем смыслов: optional поле, undefined и null — разные состояния; при exactOptionalPropertyTypes присваивание explicit undefined к optional свойству проверяется строже. Не следует бездумно применять Partial к команде обновления, если пустое значение должно означать удаление либо сброс. Для этого явно опишите семантику patch-контракта и проверьте его в runtime.

### Required.
<!-- question-id: fullstack-interview-03-typescript-core-030 -->

#### Ответ

Required<T> строится mapped type-ом, снимая optional-модификатор у всех свойств; исходные типы полей сохраняются. При опциональном name?: string результат требует name, но вопрос о допустимости undefined зависит от исходного типа и exactOptionalPropertyTypes. Часто используют Required<Pick<T, "name">> для локального ужесточения либо Partial/Required для форм конфигурации. Это compile-time требование: Required не заполняет пропущенное поле и не проверяет JSON при получении. Если данные действительно обязаны быть полными, валидируйте это runtime-схемой.

### Readonly.
<!-- question-id: fullstack-interview-03-typescript-core-031 -->

#### Ответ

Readonly<T> делает свойства T readonly на уровне TypeScript, то есть запрещает присваивание через ссылку такого типа. Это shallow: если поле содержит объект или массив, его вложенные поля не становятся readonly. Не меняется и runtime-поведение; для фактической поверхностной заморозки существует Object.freeze, а для глубокого иммутабельного контракта — отдельная рекурсивная модель и при необходимости runtime-клонирование/заморозка. readonly также не гарантирует, что объект никто не изменит через другую mutable-ссылку. Используйте его как полезное ограничение API и сигнал владения, а не как защиту безопасности.

### Pick.
<!-- question-id: fullstack-interview-03-typescript-core-032 -->

#### Ответ

Pick<T, K> создаёт тип из выбранных свойств T, где K extends keyof T. Например, Pick<User, "id" | "email"> образует read model с теми же модификаторами и типами полей. Он полезен для узких DTO и публичных контрактов, чтобы не дублировать определения; выборка не влияет на runtime-объект и не выкидывает из него другие поля. При сериализации или выдаче данных наружу нужна явная runtime-проекция: тип Pick сам не очищает чувствительные свойства.

### Omit.
<!-- question-id: fullstack-interview-03-typescript-core-033 -->

#### Ответ

Omit<T, K> исключает из T поля из K и эквивалентен по смыслу Pick<T, Exclude<keyof T, K>> для простого объектного типа. Удобен для производных форм, например удалить server-owned id у CreateUser. Однако при union сложных объектных вариантов оператор может сгладить взаимосвязь полей и дискриминанта; тогда преобразовывайте каждый union-вариант distributive conditional-ом. Omit тоже действует только на тип: он не удаляет ключ из runtime-объекта и не должен использоваться как security-фильтр без явного преобразования данных.

### Record.
<!-- question-id: fullstack-interview-03-typescript-core-034 -->

#### Ответ

Record<K, V> выражает отображение из множества ключей K в значения V. Для конечного union, например Record<"draft" | "published", Config>, объект обязан содержать все эти ключи, что удобно для исчерпывающих таблиц и конфигураций. Record<string, V> вместо этого задаёт string index signature и не гарантирует фактическое наличие произвольного ключа: чтение может быть undefined при включённом noUncheckedIndexedAccess. K должен быть допустимым ключом (PropertyKey). Это описание формы, а не фабрика объекта; свежий literal проходит проверку лишних ключей, но присвоение переменной структурно допускает дополнительные поля.

### Exclude.
<!-- question-id: fullstack-interview-03-typescript-core-035 -->

#### Ответ

Exclude<T, U> удаляет из union T те варианты, которые assignable к U: Exclude<"a" | "b" | 1, string> даёт 1. По сути, это distributive conditional T extends U ? never : T, поэтому работает по отдельным участникам union; он не вычитает подтипы из нетипового множества и не является set-theoretic complement. Например, Exclude<string, "admin"> остаётся string, потому что string как целое не assignable к литералу "admin". Тип полезен для формирования состояний/ключей, но не для runtime-фильтрации данных.
